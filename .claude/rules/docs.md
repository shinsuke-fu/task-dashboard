# ドキュメントの役割分担

- `docs/要件定義書.md` / `docs/要件定義書_プロジェクト管理機能.md`：「何を作るべきか」という
  ユーザー視点の要求。実装の内部詳細は書かない
- `docs/基本設計書.md`：アーキテクチャ・画面一覧・データモデル・ファイル対応表など、
  システムをどう構成しているかの全体像。業務で使う設計書として専門的・簡潔に保つ。
  会話的な文言（「〜という質問への回答も兼ねて」等）や合意の経緯は書かない
- `docs/詳細設計書_認証DB編.md`：DBスキーマ・RLSポリシーなど内部実装の詳細設計。同じく
  専門的・簡潔に保ち、会話的な文言や合意の経緯は書かない
- `TODO.md`：未着手・保留中のバックログのみ。「今後直す予定ではなく恒久的な仕様・制約」は
  `docs/基本設計書.md`9章へ書く（TODOと混在させない）
- `学習ノート.md`：React/TypeScript/Vite/Tailwind/Supabaseの初心者向け解説、および開発中に
  実際に起きた不具合対応の経緯・トラブルシューティングはすべてここに集約する。設計書側には
  経緯・解説を書かない
- `規約.md`：ユーザー自身が定めたAI向けの絶対ルール。事実として古くなった記述
  （アプリ名等）以外は、AIが勝手に書き換えない
- `引継ぎメモ.md`：スレッドをまたぐ一時的な最新状況スナップショット。内容が古くなったら
  都度上書きしてよい
- コミットメッセージは`commit-message-*.md`として日付付きで作成し、チャットでも同じ内容を
  提示する。このファイルはGitリポジトリにコミットしない運用（チャット経由で渡すだけの
  補助ファイル）
